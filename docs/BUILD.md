# Longhand — Build Brief

This is the shared brief for every agent building Longhand. `docs/SPEC.md` is the product spec (exported from the spec doc); this file pins the technical choices the spec leaves open. If the two conflict, the spec wins on product behavior and this file wins on technology. Progress lives in `docs/BUILD_STATUS.md`.

## The one rule

No word enters the manuscript unless a human input event put it there. The AI writes only to the annotation layer. Every design choice below serves that invariant; any code path that lets an agent-actor event change manuscript text is a release-blocking bug.

## Repo and tooling

- **pnpm workspace**, TypeScript strict, ESM everywhere, Node ≥ 22 (local is Node 25).
- Packages export TypeScript source directly (`"exports": { ".": "./src/index.ts" }`). Next.js consumes them via `transpilePackages`; Node services run with `tsx`. No per-package build step except the verifier CLI bundle.
- **Vitest** for unit/property tests (`fast-check` for property tests). **Playwright** for end-to-end, run against Chrome (`channel: 'chrome'`) or the bundled Chromium.
- Root scripts: `pnpm typecheck`, `pnpm test`, `pnpm lint`, `pnpm dev` (everything locally), `pnpm e2e`.
- Prettier + ESLint (flat config). Keep config minimal.

## Pinned technical choices

- **UI**: React 19 + Next.js (App Router) in `apps/web`. UI packages export React components and plain ProseMirror plugins. Styling: CSS modules or plain CSS with CSS variables; no UI framework. Calm, typographic, light and dark.
- **Editor model**: ProseMirror. The document schema lives in `packages/schema` so the fold, the editor, export and the agent all share it. Manuscript edits travel as `prosemirror-transform` Step JSON inside `TextEdited`.
- **Fold**: pure and deterministic. Same events in, byte-identical document JSON + provenance out, in Node and in the browser. No `Date.now()`, no locale-dependent APIs, no `Intl.Segmenter` (ICU differs across runtimes) — the sentence segmenter is rule-based code in `packages/schema`.
- **Provenance**: derived only by the fold, as runs over document positions, each run carrying class + originating event seq. Never stored as editable marks.
- **Proposals**: an accepted move/cut/split/merge is recorded as `ProposalAccepted { proposalId }`; the fold derives the steps itself from the proposal and the current document, so moved words keep their provenance and no new words can enter.
- **Hashing**: SHA-256 over RFC 8785 canonical JSON (JCS) of the commit minus `hash`. `prevHash` of the first commit is 64 zeros.
- **Witness signatures**: ECDSA P-256 / SHA-256 (supported by AWS KMS `ECC_NIST_P256` and by WebCrypto, so the browser verifier works). Signed message = canonical JSON of `{projectId, seq, hash, serverTime}`. Locally a PEM key in `.dev/witness-key.pem` (generated by `pnpm dev:setup`, gitignored); prod uses KMS behind the same `Signer` interface.
- **Ledger storage**: one Durable Stream per project (`@durable-streams/server` reference server locally, `@durable-streams/client` from the ledger service). The ledger service is the only writer. Postgres holds the read model (projects, documents, folded state snapshots, annotations, sources) and is rebuildable from streams.
- **Migrations**: numbered SQL files in `apps/server/migrations`, applied by a tiny runner. Only the server lane writes them.
- **Auth**: Amazon Cognito in prod (JWT verified with `aws-jwt-verify`). Locally `AUTH_MODE=dev` signs in a fixed dev user with no external calls. Every row and stream is keyed by `accountId`.
- **AI runtime**: the agent runs the local Claude Code CLI headlessly — `claude -p --output-format stream-json --verbose --tools "" --strict-mcp-config --mcp-config <generated> --allowedTools "mcp__longhand__*" --no-session-persistence --system-prompt <prompt> --model <model>`. Built-in tools are disabled; the only tools are Longhand's annotation tools, served by an MCP stdio server from `packages/agent`. That server validates every call and forwards it to the ledger service as an agent-actor event. A `MockModelAdapter` replays scripted tool calls for tests; no test may require a live model.
- **Models**: full reviews `opus`, selection-sized passes `sonnet` (CLI aliases; configurable).
- **Ports (local)**: web 3100, ledger service 3200, Durable Streams 3300, Postgres 5434 (Docker Compose).

## How lanes work

- Work only inside your lane's paths. If you need a contract change (new event type, schema field, tool argument), stop and report exactly what you need; do not edit `packages/schema` or `packages/ledger`.
- Test against the golden fixtures in `packages/ledger/fixtures` and the mocks, not against other lanes.
- Done = `pnpm --filter <your package> typecheck` and `test` pass, plus the repo-wide `pnpm typecheck`. Commit in small, logical commits with clear messages.
- Write a short `README.md` in your package: what it exports, how to run its tests, known gaps.
